# 투명 프록시

투명 프록시를 켜면 애플리케이션에서 별도로 설정하지 않아도 트래픽이 코어에 도달합니다. 적용 범위는 구현 방식에 따라 다릅니다. **설정 → 투명 프록시/시스템 프록시**에서 켜고 트래픽 분할 정책을 선택합니다. 그 아래 설정에서 구현 방식을 선택합니다.

## 정책

| 정책                | 프록시를 통과하는 트래픽                                                                                                                                                                                        |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 트래픽을 분할하지 않음          | 모든 트래픽                                                                                                                                                                                                       |
| 중국 사이트 외 프록시 | 중국 도메인과 주소(`geosite:cn`, `geoip:cn`), 사설 주소를 제외한 모든 트래픽. 중국 관련 규칙과 일치하더라도 중국 외 사이트, Google, 홍콩과 마카오 주소에는 프록시 적용 |
| GFWList만 프록시    | GFWList의 도메인(Loyalsoldier 파일의 `gfw`, `greatfire`)과 Telegram 주소 범위. 먼저 **GFWList 업데이트**를 실행해야 하며, 파일이 없으면 이 모드는 거부됨                                    |
| 규칙 포트와 동일 | RoutingA를 포함한 규칙 포트의 모드                                                                                                                                                                         |

## 구현 방식

| 구현 방식 | 플랫폼                                                    | 참고                                                                                                        |
| -------------- | ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| `redirect`     | Linux                                                        | iptables/nftables `REDIRECT`. TCP만 지원하며, 포트 53의 DNS도 코어의 DNS 모듈(포트 52353)로 리디렉션 |
| `tproxy`       | Linux                                                        | iptables/nftables `TPROXY`. TCP와 UDP 지원                                                                      |
| `tun`          | Linux, Windows, macOS                                        | 코어가 TUN 장치를 엶. TCP와 UDP 지원. v2rayA와 코어를 자동으로 제외                             |
| 시스템 프록시   | Windows. Linux와 macOS에서는 root 권한 없이 실행할 때(`--lite`) | 데스크톱의 프록시 설정을 변경(Linux에서는 GNOME과 KDE). 해당 설정을 따르는 애플리케이션에만 적용   |

`redirect`와 `tproxy`에는 root 권한과 `iptables` 또는 `nftables`가 필요합니다. `tun`에는 Linux에서 `/dev/net/tun`과 `ip`가, Windows와 macOS에서 관리자 권한이 필요합니다.

**제외할 인터페이스 접두사**는 지정한 인터페이스(Docker 브리지, VPN 터널. 기본값은 `docker*`, `veth*`, `wg*`, `ppp*`)로 들어오는 트래픽이 `redirect`와 `tproxy`를 거치지 않게 합니다. 해당 트래픽의 DNS는 여전히 가로챕니다.

## TUN

코어가 TUN 장치를 생성하고 주소를 할당합니다. **자동 라우트**를 켜면 v2rayA가 라우팅 경로를 설정하고 시스템 리졸버가 코어를 사용하도록 설정합니다. 끄면 **라우트 스크립트 구성**의 설정 및 해제 스크립트가 이 작업을 수행합니다.

코어 자체의 연결, `direct` 아웃바운드, DNS 모듈의 업스트림 질의는 TUN에 들어가지 않습니다(Linux에서는 소켓 마크를 사용하고, Windows와 macOS에서는 물리 인터페이스에 바인딩). v2rayA와 코어는 항상 제외됩니다. **TUN 제외 프로세스**에 실행 파일 이름을 한 줄에 하나씩 입력하면 소유 프로세스를 식별할 수 있는 연결을 추가로 제외합니다. 해당 프로세스의 DNS는 여전히 코어의 DNS 모듈로 전달됩니다. 기본 라우트보다 구체적인 라우트(직접 연결된 네트워크, 정적 라우트)도 TUN을 우회합니다.

TUN에 도달한 포트 53의 암호화되지 않은 DNS에는 코어의 DNS 모듈이 DNS 규칙에 따라 응답합니다. 암호화된 DNS는 가로채지 않습니다. Windows에서는 시스템 리졸버가 TUN 게이트웨이를 사용하도록 설정하고, macOS에서는 `127.0.0.1`의 코어 리스너를 사용하도록 설정하므로 포트 53이 비어 있어야 합니다.

알려진 제한 사항: Windows와 macOS에서 LAN 리졸버에 직접 질의하는 애플리케이션은 여전히 TUN을 우회합니다.

## DNS

**설정 → DNS 설정**에는 코어의 DNS 모듈이 따르는 규칙이 있습니다. 어떤 업스트림이 어떤 도메인에 응답할지, 질의를 직접 보낼지 지정합니다. 기본값은 내부 도메인 이름에 대한 DNS 질의를 `127.0.0.1:53`으로 보내고(`localhost`, 해당 주소에서 수신하는 리졸버 필요), `geosite:cn`은 `223.5.5.5`로 직접 보내며, 나머지는 프록시를 통해 `1.0.0.1`로 보냅니다. 아웃바운드가 `direct`이면 직접 질의합니다. 다른 값이면 로컬 SOCKS 인바운드를 통해 질의를 보내므로 SOCKS 트래픽과 같은 방식으로 라우팅됩니다. 도메인 목록이 비어 있는 규칙은 다른 규칙에서 지정하지 않은 모든 도메인에 응답합니다. 업스트림에는 주소(`8.8.8.8`, `dns.google`), `tcp://host`, DNS over TLS용 `tls://host`, DNS over HTTPS용 `https://host/dns-query`를 사용할 수 있습니다. DNS over QUIC는 지원하지 않으며 저장 시 거부됩니다.

## LAN 공유

**포트 공유**를 켜면 SOCKS, HTTP, 사용자 지정 인바운드가 `127.0.0.1` 대신 모든 인터페이스에서 수신하므로 다른 장치가 이 컴퓨터를 프록시로 사용할 수 있습니다. API 포트는 계속 루프백에서 수신합니다. 다른 장치의 트래픽에도 투명 프록시를 적용하려면 `redirect`, `tproxy` 또는 `tun`을 사용하고, **IP 포워딩**을 켜고, 트래픽이 들어오는 인터페이스가 제외 접두사에 포함되지 않게 한 다음, 해당 장치의 기본 게이트웨이를 이 컴퓨터로 지정하세요. 시스템 프록시 모드에서는 이 기능을 사용할 수 없습니다.
