# 빠른 시작

브라우저의 이 페이지에서 v2rayA를 설정하고 상태를 확인합니다. 서비스는 root 권한으로 실행되며(Windows에서는 관리자 권한, `--lite` 사용 시에는 일반 사용자 권한) `v2raya_core`를 직접 시작합니다.

## 로그인

처음 등록한 계정이 관리자이며, 다른 계정은 없습니다. 등록할 때는 사용자 이름과 6~32자의 비밀번호를 입력하며 기존 인증 정보는 필요하지 않습니다. 따라서 공유 네트워크에서는 등록 전에 포트 2017에 접근할 수 있는 사용자를 제한하거나, `--address 127.0.0.1:2017`로 서비스를 실행해 로컬에서만 사용하세요.

비밀번호를 잊었다면 서비스를 중지한 상태에서 명령줄로 재설정합니다.

```sh
v2raya --reset-password
```

서비스가 사용하는 계정과 `--config` 디렉터리로 실행하세요(lite 모드에서는 `--lite`도 사용). Windows에서는 서비스가 SYSTEM 계정으로 실행되며, 관리자 권한으로 실행한 사용자의 디렉터리와 서비스의 디렉터리가 다릅니다. 서비스를 다시 시작하고 새 계정을 등록하세요.

## 노드 가져오기

**프록시** 페이지의 **가져오기**에서 공유 링크나 구독을 가져옵니다. **서버 링크**를 선택하면 `vmess://`, `vless://`, `ss://`, `trojan://`, `hysteria2://`, `tuic://`, `juicity://`, `anytls://`, `wireguard://`, `socks5://`, `http://`, `https://` 링크를 한 줄에 하나씩 입력하거나 QR 코드 이미지를 사용할 수 있습니다. 구독을 가져오려면 **구독 주소**를 선택하세요. ShadowsocksR 링크는 거부되며, 스트림 암호(`rc4-md5`, `aes-*-cfb`, `chacha20-ietf`)나 `none`을 쓰는 Shadowsocks 링크도 거부됩니다. 코어는 AEAD 암호와 2022-blake3 방식만 받습니다. 링크의 `allow_insecure`는 무시됩니다. v2rayA는 인증서 검증을 건너뛰지 않으므로, 자체 서명 서버는 노드 양식에 인증서 SHA-256을 고정하세요.

구독은 **구독** 페이지에 따로 있습니다(휴대폰에서는 자리를 내기 위해 문서 항목이 상단 바 메뉴로 옮겨집니다). 구독에 속한 노드는 함께 관리되며, 수동으로 또는 예약에 따라 업데이트할 수 있습니다(**설정 → 구독 자동 업데이트**). 옆의 모드 설정은 업데이트할 때 프록시를 사용할지 결정합니다.

## 그룹

노드는 프록시 그룹을 통해 사용합니다. `proxy` 그룹은 항상 존재하며, 다른 그룹은 상단 바의 그룹 버튼에서 만들고 설정하고 삭제하며, 그룹 관리는 그곳에서만 합니다. 노드는 노드 메뉴에서 그룹에 넣거나, 프록시 페이지에서 여러 개를 선택한 뒤 **프록시 그룹에 추가**에서 그룹을 고릅니다. 연결된 구성원이 여러 개인 그룹은 측정된 지연 시간이 가장 짧은 노드를 사용합니다(**자동 (최저 지연 시간)**). 대시보드의 노드 메뉴에서 구성원 하나를 고정하면 그룹은 해당 노드만 사용합니다. **노드 추가/삭제**에서 구성원을 변경하고, 그룹 설정에서 지연 시간 측정에 사용할 주소와 측정 간격을 설정합니다.

라우팅 규칙에서는 그룹 이름으로 아웃바운드를 지정합니다. 기본값은 `proxy`이며, 다른 그룹도 연결된 구성원이 있으면 그룹 이름으로 지정할 수 있습니다.

## 코어 시작

대시보드의 **시작** 또는 페이지 상단의 상태 버튼을 누르면 현재 설정으로 `v2raya_core`를 시작합니다. 설정 페이지의 변경 사항은 **저장 및 적용**을 눌러 적용합니다. 실행 중인 코어는 변경된 설정으로 다시 시작하며, 중지된 코어는 다음 시작 시 적용합니다.

코어가 실행되면 애플리케이션은 로컬 인바운드를 통해 코어에 연결합니다.

| 인바운드       | 주소              | 라우팅                                |
| -------------- | ----------------- | ------------------------------------- |
| SOCKS5         | `127.0.0.1:20170` | 모든 트래픽을 `proxy`로 전달          |
| HTTP           | `127.0.0.1:20171` | 모든 트래픽을 `proxy`로 전달          |
| 규칙 적용 HTTP | `127.0.0.1:20172` | **규칙 포트의 트래픽 분할 모드** 설정 |

포트는 **설정 → 주소 및 포트**에서 변경합니다. 0으로 설정하면 인바운드가 닫힙니다. 애플리케이션을 각각 설정하지 않고 프록시를 적용하려면 투명 프록시를 켜세요.

## 라우팅

**설정 → 트래픽 분할**에서 규칙 포트와 투명 프록시의 트래픽 분할 방식을 선택합니다. 중국 사이트를 제외한 모든 트래픽에 프록시를 적용하거나, GFWList에만 적용하거나, 직접 작성한 RoutingA 규칙을 사용할 수 있습니다. RoutingA는 별도 섹션에서 설명합니다.

## 키보드

- 프록시 페이지 목록 보기: `Ctrl`+`A`는 표시된 모든 노드를 선택하고 `Esc`는 선택을 해제합니다. 프록시와 로그 페이지에서 `/`는 검색창으로 이동합니다.
- 설정: `Ctrl`+`S`로 저장합니다. RoutingA 편집기: `Ctrl`+`S` 저장, `Tab` 들여쓰기.
- 여러 줄 입력이 있는 대화 상자(가져오기, 구독, 라우팅 스크립트, 목록): `Ctrl`+`Enter`로 제출하고 `Esc`로 어떤 대화 상자든 닫습니다.
- 로그: 포커스가 있으면 `Home`, `End`, `PgUp`, `PgDn`으로 이동합니다.

macOS에서는 `Cmd`가 `Ctrl`을 대신합니다.

## 구독 자동 업데이트

각 구독마다 업데이트 모드를 선택할 수 있습니다.

- **사용 안 함:** 수동으로 요청할 때만 업데이트합니다.
- **서비스 시작 시:** v2rayA가 시작될 때마다 한 번 업데이트합니다.
- **주기적으로:** 시작할 때 업데이트한 뒤 설정한 분 간격으로 업데이트합니다.
- **주기적 업데이트 및 장애 복구:** 정기 일정에 더해 장애 간격으로 저장된 서버를 확인합니다. 모든 서버를 사용할 수 없으면 하나 이상 복구될 때까지 해당 간격으로 구독을 새로 고칩니다.

다운로드가 실패하거나 빈 응답을 받으면 저장된 서버 목록을 유지합니다. 장애 재시도는 정기 업데이트를 미루지 않으며, 오래 걸리는 확인 작업은 다음 작업과 겹쳐 실행되지 않습니다. Linux에서는 복구 다운로드가 표시된 소켓을 사용하므로 투명 프록시가 요청을 고장 난 프록시로 다시 보내지 않습니다. macOS 또는 Windows의 TUN 모드에서는 이 우회가 보장되지 않습니다. 서버 확인을 위해 임시 코어 프로세스가 시작될 수 있지만, 사용자가 수동으로 중지한 주 코어는 자동 업데이트가 시작하지 않습니다.

업그레이드 시 기존 전역 “시작할 때 업데이트” 설정은 모든 기존 구독의 **서비스 시작 시** 모드로 이전됩니다. 기존 주기 모드는 시간을 분으로 변환한 **주기적으로** 모드가 됩니다. 장애 복구는 자동으로 활성화되지 않으므로 필요한 구독에서 직접 선택해야 합니다.
