# 문제 해결

먼저 서비스 로그를 확인하세요. Linux 서비스 유닛으로 실행할 때는 `/var/log/v2raya/v2raya.log`, 유닛 자체의 출력은 `journalctl -u v2raya`, 그 외에는 `--log-file`로 지정한 경로에서 확인합니다. **로그** 페이지에서도 같은 로그 스트림을 볼 수 있습니다. **로그 수준** 설정을 조정하면 코어가 더 상세한 로그를 출력합니다. 생성된 코어 설정은 설정 디렉터리의 `config.json`입니다.

## 코어가 시작되지 않음

`CORE_START_FAILED`는 `v2raya_core`를 실행하지 못했거나, 시작 직후 종료되었거나, `--core-startup-timeout` 안에 API 포트를 열지 못했다는 뜻입니다. 로그에서 그 앞의 줄을 보면 원인을 알 수 있습니다. 일반적인 원인은 다음과 같습니다.

- **코어 버전 불일치** — 페이지 상단의 배너입니다. `v2raya_core`는 `v2raya`와 버전이 같아야 합니다. 대신 `xray`나 `v2ray` 바이너리를 사용하는 것은 허용되지 않습니다. 둘 다 같은 릴리스에서 설치하세요.
- **`illegal domain rule: geosite:...`** — 규칙이 `geosite.dat`에 없는 카테고리를 지정합니다. 사용 가능한 이름은 라우팅 섹션을 참고하세요.
- **address already in use** — 인바운드 포트를 다른 프로그램이 사용 중입니다. 주소 및 포트에서 변경하거나 다른 프로그램을 중지하세요. 포트 53은 다르게 처리됩니다. 사용 중이면 DNS 모듈은 해당 포트에서 리스너를 열지 않고 로그에 이를 남기며, macOS에서는 기존 리졸버가 계속 응답합니다.
- **`v2raya_core executable not found`** — 코어 실행 파일이 `v2raya`와 같은 디렉터리에도, `PATH`에 지정된 디렉터리에도 없습니다. `--v2ray-bin`을 지정하세요.

## 아무것도 연결되지 않음

- 대시보드는 그룹과 구성원의 지연 시간을 표시합니다. `TIMEOUT`은 이 컴퓨터에서 서버로 TCP 연결을 맺지 못했다는 뜻입니다. 다른 노드를 사용하거나 구독을 확인하세요.
- 인바운드 하나를 직접 테스트하세요: `curl -x socks5h://127.0.0.1:20170 https://example.com`. 이 명령은 성공하지만 투명 프록시가 작동하지 않으면, 노드 문제로 판단하기 전에 투명 프록시 설정, DNS 규칙, 투명 프록시가 트래픽을 보내는 그룹을 확인하세요.
- `redirect`나 `tproxy`를 사용한다면 Docker 또는 방화벽이 iptables 규칙을 덮어썼을 수 있습니다. 코어를 중지했다가 시작해 규칙을 다시 적용하세요.
- Windows와 macOS에서 LAN 리졸버에 직접 DNS를 질의하는 애플리케이션은 TUN을 우회합니다.

## 규칙 데이터

코어를 찾은 뒤 `geoip.dat`나 `geosite.dat` 없이 시작하면 GitHub에서 없는 파일을 다운로드하고, 다운로드에 실패하면 종료합니다. 파일을 규칙 데이터 디렉터리에 직접 복사하거나(매개변수 섹션 참고), 파일을 포함한 패키지를 설치하세요.

## 업그레이드 후

이전 릴리스의 BoltDB 데이터베이스는 처음 시작할 때 마이그레이션됩니다. 기존 파일은 `bolt.db.bak`으로 남으며(해당 이름이 이미 있으면 `bolt.db.bak.1`부터 번호 증가), 계정은 다시 등록해야 합니다. 업그레이드 전에 서비스를 중지하고 설정 디렉터리를 복사해 두세요. 그러면 복사본에서 마이그레이션을 다시 진행할 수 있습니다.

## 비밀번호 재설정

서비스를 중지하고, 서비스가 사용하는 계정으로 같은 `--config` 및 `--lite` 플래그를 지정해 `v2raya --reset-password`를 실행한 다음, 서비스를 다시 시작하고 등록하세요(Windows에서 서비스의 디렉터리는 관리자 권한으로 실행한 사용자의 디렉터리가 아니라 `%ProgramData%\SYSTEM` 아래에 있음).
