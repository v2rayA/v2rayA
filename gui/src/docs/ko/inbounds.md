# 인바운드와 공유

인바운드는 코어가 애플리케이션이나 다른 장치의 연결을 받는 포트입니다.

## 기본 제공 인바운드

**설정 → 주소 및 포트**에서 설정합니다. 0으로 설정하면 프록시 인바운드는 닫히고, API 포트는 무작위로 선택됩니다.

| 인바운드         | 기본값  | 라우팅                                                   |
| ---------------- | ------- | -------------------------------------------------------- |
| SOCKS5           | `20170` | 모든 트래픽을 `proxy`로 전달                             |
| HTTP             | `20171` | 모든 트래픽을 `proxy`로 전달                             |
| 규칙 적용 SOCKS5 | 꺼짐    | 규칙 포트의 모드                                         |
| 규칙 적용 HTTP   | `20172` | 규칙 포트의 모드                                         |
| 규칙 적용 VMess  | 꺼짐    | 다른 장치를 위한 VMess 인바운드. 페이지에 공유 링크 표시 |
| API              | 무작위  | v2rayA가 통계와 부하 분산에 사용하는 코어 자체 API       |

프록시 인바운드는 `127.0.0.1`에서 수신합니다. **포트 공유**(설정 → 프록시)를 켜면 모든 인터페이스에서 수신하므로 LAN의 휴대전화와 다른 컴퓨터도 사용할 수 있습니다. API 포트는 계속 루프백에서 수신합니다. 신뢰할 수 없는 네트워크에서는 다른 장치용으로 사용자 이름과 비밀번호가 있는 사용자 지정 인바운드를 추가하고, 비밀번호를 받지 않는 기본 제공 SOCKS 및 HTTP 포트를 닫거나 방화벽에서 차단하세요.

## 사용자 지정 인바운드

**설정 → 사용자 지정 인바운드 포트**에서 별도의 포트, 선택적인 사용자 이름과 비밀번호, 자체 라우팅을 갖는 SOCKS 또는 HTTP 인바운드를 추가합니다. 라우팅은 고정된 프록시 그룹을 사용하거나 해당 인바운드용 RoutingA 규칙을 사용합니다. 규칙에 일치하지 않는 트래픽은 선택한 그룹으로 보냅니다(여기서는 `default:` 무시). 따라서 사용자 지정 인바운드 두 개로 트래픽을 서로 다른 두 그룹에 보낼 수 있으며, 규칙이 `network(tcp, udp) -> direct`로 끝나는 인바운드는 해당 인바운드를 사용하도록 설정한 모든 애플리케이션의 트래픽을 프록시 없이 전달합니다.

태그는 코어 설정과 `inboundTag(...)` 조건에서 사용하는 인바운드 이름입니다.

## Docker와 포트 매핑

`--network=host`로 시작한 컨테이너에서는 인바운드와 투명 프록시가 호스트에 적용됩니다. 브리지 네트워크에서는 포트 2017과 사용할 인바운드 포트를 공개하고, 포트 공유를 켜서 컨테이너의 인터페이스에서 수신하게 하세요. 이때 투명 프록시는 컨테이너의 트래픽만 처리합니다. v2rayA는 매핑된 포트가 호스트에서 비어 있는지 판단할 수 없습니다.
