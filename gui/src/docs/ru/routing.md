# Правила маршрутизации

RoutingA — язык правил v2rayA. Раздел **Настройки → Правила RoutingA** открывает редактор; правила применяются к порту правил (`20172`), когда для него выбран режим RoutingA, и к прозрачному прокси, когда для него выбран режим _Режим разделения трафика совпадает с режимом порта правил_. У пользовательского входящего порта, привязанного к RoutingA, свой текст правил; см. ниже.

## Синтаксис

Одно правило в строке: условия, соединённые `&&`, затем `->` и исходящее подключение. Правила проверяются сверху вниз, применяется первое совпавшее; `default:` задаёт исходящее подключение для всего, что не подошло ни под одно правило. Строка, начинающаяся с `#`, — комментарий. v2rayA добавляет несколько собственных правил в начало: адреса прокси-серверов и служба push-уведомлений Apple идут напрямую, а условие `inboundTag(...)` заменяет обычное ограничение правила по входящим портам.

```
default: proxy
domain(geosite:category-ads-all) -> block
domain(geosite:cn) -> direct
ip(geoip:private, geoip:cn) -> direct
```

| Условие | Соответствие |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `domain(...)` | `domain:` — домен и его поддомены, `full:` — точное совпадение, `regexp:`, `geosite:<category>`, `ext:"file.dat:tag"`; значение без префикса, например `example.com`, ищется как подстрока |
| `ip(...)` | адрес, CIDR (IPv6 заключайте в кавычки: `ip("2001:db8::/32")`), `geoip:<code>`, `ext:"file.dat:tag"` |
| `port(...)` | порты назначения и диапазоны, `port(80, 443, 1000-2000)` |
| `sourcePort(...)` | порты источника |
| `network(...)` | `tcp`, `udp` |
| `protocol(...)` | протокол, определённый анализом трафика: `http`, `tls`, `quic`, `bittorrent` (нужно включить **Анализ входящего трафика**) |
| `source(...)` | адреса и диапазоны CIDR источника |
| `inboundTag(...)` | входящий порт, через который поступило соединение |

## Исходящие подключения

`proxy`, `direct` и `block` встроены. Любая другая группа прокси становится исходящим подключением под своим именем, как только у неё появляется подключённый участник; иначе правила не применяются. Сервер SOCKS или HTTP вне v2rayA объявляется один раз и используется как группа (файл `ext:` помещается в каталог данных правил):

```
outbound: office = socks(address: 192.168.1.10, port: 1080)
outbound: gateway = http(address: 10.0.0.1, port: 8080, user: 'name', pass: 'secret')
domain(domain: corp.example) -> office
```

## Категории

Категории `geosite:` берутся из [domain-list-community](https://github.com/v2fly/domain-list-community) проекта v2fly, а коды `geoip:` — из [v2fly/geoip](https://github.com/v2fly/geoip); при первом запуске v2rayA скачивает недостающие файлы, пакет может содержать собственную сборку этих файлов. Часто используются: `geosite:cn`, `geosite:geolocation-!cn`, `geosite:private`, `geosite:category-ads-all`, `geosite:greatfire`, `geosite:netflix`, `geosite:youtube`, `geosite:telegram`, `geosite:openai`; `geoip:cn`, `geoip:private` и коды стран. Атрибут сужает категорию: `geosite:apple@cn`, `geosite:category-games@cn`.

Имена, которые есть только в сборках Loyalsoldier (`gfw`, `apple-cn`, `google-cn`, `geoip:telegram`), отсутствуют в этих файлах; ядро отклоняет их с ошибкой `illegal domain rule` или `illegal ip rule`. Кнопка **Обновить GFWList** скачивает эту сборку (из `v2rayA/dist-v2ray-rules-dat`) как `LoyalsoldierSite.dat`, после чего правила могут использовать её как `domain(ext:"LoyalsoldierSite.dat:gfw")`.

## Редактор

В режиме списка каждое правило редактируется через форму; текстовый режим показывает номера строк, подсветку и результат проверки каждой строки. Справочник рядом с редактором вставляет примеры в позицию курсора, а раздел **Шаблоны** содержит полные наборы правил для распространённых режимов: вставьте один перед своими правилами или замените им весь набор. Правила импортируются и экспортируются в виде текстового файла.

При сохранении работающее ядро перезагружается с новыми правилами; если ядро их отклоняет, v2rayA возвращает предыдущие правила и показывает ошибку ядра с указанием некорректного текста. Остановленное ядро применяет правила при следующем запуске.

## Пользовательские входящие порты

У пользовательского входящего порта, привязанного к RoutingA, свой текст правил, действующий только для этого порта. Он принимает правила, а не определения: строки `default:` и `outbound:` игнорируются, а трафик, не подошедший ни под одно правило, идёт в группу, выбранную в форме. Завершите текст правилом для всего оставшегося трафика, например `network(tcp, udp) -> direct`, чтобы самостоятельно задать его маршрут.
