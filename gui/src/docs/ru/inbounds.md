# Входящие порты и общий доступ

Входящий порт — порт, на котором ядро принимает соединения от приложений или других устройств.

## Встроенные входящие порты

Раздел **Настройки → Адреса и порты** задаёт их; 0 закрывает входящий порт прокси, а для порта API означает случайный выбор.

| Входящий порт | По умолчанию | Маршрутизация |
| ----------------- | ------- | ------------------------------------------------------------------ |
| SOCKS5 | `20170` | всё через `proxy` |
| HTTP | `20171` | всё через `proxy` |
| SOCKS5 с правилами | выключен | режим порта правил |
| HTTP с правилами | `20172` | режим порта правил |
| VMess с правилами | выключен | входящий порт VMess для других устройств; страница показывает ссылку для подключения |
| API | случайный | собственный API ядра, используемый v2rayA для статистики и балансировщика |

Входящие порты прокси слушают на `127.0.0.1`. Параметр **Общий доступ к портам** (Настройки → Прокси) заставляет их слушать на всех интерфейсах, чтобы ими могли пользоваться телефоны и другие компьютеры в локальной сети; порт API остаётся на петлевом интерфейсе. В недоверенной сети добавьте для других устройств пользовательский входящий порт с именем пользователя и паролем и закройте встроенные порты SOCKS и HTTP, которые не требуют пароля, либо заблокируйте их межсетевым экраном.

## Пользовательские входящие порты

Раздел **Настройки → Пользовательские входящие порты** добавляет входящие подключения SOCKS или HTTP со своим портом, необязательными именем пользователя и паролем и собственной маршрутизацией: либо через фиксированную группу прокси, либо по правилам RoutingA для этого входящего порта, с выбранной группой при отсутствии совпадений (`default:` здесь игнорируется). Поэтому два пользовательских входящих порта могут отправлять трафик в две разные группы, а входящий порт, чьи правила заканчиваются на `network(tcp, udp) -> direct`, обходит прокси для каждого приложения, настроенного на этот порт.

Тег — это имя входящего порта в конфигурации ядра и в условиях `inboundTag(...)`.

## Docker и сопоставление портов

В контейнере, запущенном с `--network=host`, входящие порты и прозрачный прокси действуют на хосте. При использовании мостовой сети опубликуйте порт 2017 и используемые входящие порты, а также включите общий доступ к портам, чтобы они слушали на интерфейсах контейнера; прозрачный прокси в этом случае видит только контейнер. v2rayA не может определить, свободен ли сопоставленный порт на хосте.
