# 入站与共享

入站是内核接受应用或其他设备连接的端口。

## 内置入站

在**设置 → 地址与端口**设置，0 表示关闭。

| 入站 | 默认 | 分流 |
| --- | --- | --- |
| SOCKS5 | `20170` | 与透明代理设置相同，未开透明代理时全部走代理 |
| HTTP | `20171` | 同上 |
| 带规则的 SOCKS5 | 关闭 | 规则端口的模式 |
| 带规则的 HTTP | `20172` | 规则端口的模式 |
| 带规则的 VMess | 关闭 | 供其他设备连接的 VMess 入站；页面显示它的分享链接 |
| API | 随机 | 内核自己的 API，v2rayA 用它取统计数据和负载均衡状态 |

入站监听 `127.0.0.1`。**允许局域网的连接**（设置 → 代理）让它们监听所有网卡，局域网里的手机和其他机器就能使用；网络不属于你时，用自定义入站给 SOCKS 与 HTTP 加上密码。

## 自定义入站

**设置 → 自定义入站端口**添加 SOCKS 或 HTTP 入站，各自有端口、可选的用户名密码和独立的分流：绑定到固定的代理分组，或者为该入站单独写一组 RoutingA 规则。两个自定义入站可以把流量送到两个不同的分组；也可以让指向某个入站的整个应用绕过代理。

标签是该入站在内核配置中的名称，也是 `inboundTag(...)` 条件里的名称。

## Docker 与端口映射

以 `--network=host` 启动的容器，入站就是宿主机的入站。使用桥接网络时，映射 2017 端口和用到的入站端口，并开启“允许局域网的连接”让入站监听容器的网卡；这种方式没有透明代理。v2rayA 无法判断映射的端口在宿主机上是否空闲。
