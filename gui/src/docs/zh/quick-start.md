# 快速开始

浏览器里的这个页面用来配置 v2rayA 和查看状态；服务以 root 运行（Windows 上为管理员，`--lite` 则无需特权）并自行启动 `v2raya_core`。

## 登录

第一个注册的账户就是管理员，没有其他账户。注册时设置用户名和 6 到 32 个字符的密码，不需要已有凭据，因此在共享网络中先限制谁能访问 2017 端口再注册，或者只在本机使用时以 `--address 127.0.0.1:2017` 启动服务。

忘记密码时停止服务，在命令行重置：

```sh
v2raya --reset-password
```

以服务所用的账户执行，并带上服务所用的 `--config` 目录（lite 模式再加 `--lite`）；Windows 上服务以 SYSTEM 运行，它的目录与提权用户的不同。然后重新启动服务并注册新账户。

## 导入节点

最多同时运行一个检测核心。TCP 延迟决定顺序；URL 和完整的 256 KiB 样本验证至少 100 KiB/s。无合格服务器时阻断组流量。

订阅有自己的页面**订阅**（手机上文档入口移到顶栏菜单，给它腾出位置）。订阅的节点归在一起，可手动更新，也可按计划更新（**设置 → 自动更新订阅**）。旁边的模式选项决定更新是否经过代理。

## 分组

节点通过代理分组使用。分组 `proxy` 始终存在，其他分组在顶栏的分组按钮里创建、设置和删除，那里是分组功能的唯一入口。从节点菜单把节点加入分组，或在代理页多选后在**添加到代理组**里选分组。组内有多个已连接成员时使用实测延迟最低的成员（**自动（延迟最低）**）；在仪表板的节点菜单里可指定一个成员，此后该组只经它出站；**增删节点**修改成员，分组设置里设定探测地址与间隔。

测量所有服务器的 TCP 延迟，按延迟顺序逐个测速，找到首个合格服务器即停止。 只检查当前服务器。URL 失败或速度低于 100 KiB/s 时，按 TCP 延迟和速度选择替代服务器。 逐个检查成员，在通过 URL 和速度检测的服务器之间轮流分配新连接。 测量延迟后随机排列可达服务器，逐个测速，直到找到合格服务器。

最多同时运行一个检测核心。TCP 延迟决定顺序；URL 和完整的 256 KiB 样本验证至少 100 KiB/s。无合格服务器时阻断组流量。

分流规则以分组名作为出口：默认是 `proxy`，其他分组在有已连接成员后按名称使用。

## 启动内核

仪表板的**启动**或页面顶部的状态按钮以当前配置启动 `v2raya_core`。设置页的修改在**保存并应用**后生效：内核运行中会带着新配置重启，已停止的内核在下次启动时读取。

内核运行后，应用通过本机入站使用它：

| 入站          | 地址              | 分流                       |
| ------------- | ----------------- | -------------------------- |
| SOCKS5        | `127.0.0.1:20170` | 全部走 `proxy`             |
| HTTP          | `127.0.0.1:20171` | 全部走 `proxy`             |
| 带规则的 HTTP | `127.0.0.1:20172` | **规则端口的分流模式**设置 |

端口在**设置 → 地址与端口**修改，0 表示关闭该入站。要覆盖应用而不逐个配置，请开启透明代理。

## 分流

**设置 → 流量分流**决定规则端口和透明代理如何分流：国内站点直连其余走代理、只代理 GFWList，或者自己写的 RoutingA 规则。RoutingA 见单独一节。

## 快捷键

- 代理页列表视图：`Ctrl`+`A` 选中列出的全部节点，`Esc` 取消选择；代理页与日志页 `/` 跳到搜索框。
- 设置页：`Ctrl`+`S` 保存。RoutingA 编辑器：`Ctrl`+`S` 保存，`Tab` 缩进。
- 带多行文本框的对话框（导入、订阅、路由脚本、各类列表）：`Ctrl`+`Enter` 提交；`Esc` 关闭任何对话框。
- 日志页获得焦点后 `Home`、`End`、`PgUp`、`PgDn` 翻动日志。

macOS 上 `Cmd` 对应 `Ctrl`。

## 自动更新订阅

每个订阅都可以单独选择更新模式：

- **关闭：** 仅在手动操作时更新。
- **服务启动时：** 每次 v2rayA 启动时更新一次。
- **按间隔：** 启动时更新一次，之后按设定的分钟间隔更新。
- **按间隔并启用故障恢复：** 按正常计划更新，并按故障间隔检查已保存的服务器。全部不可用时，按该间隔刷新订阅，直到至少一个服务器恢复可用。

下载失败或返回空内容时会保留已保存的服务器列表。故障重试不会推迟定时更新，耗时较长的一轮检查也不会与下一轮并行。在 Linux 上，恢复下载使用带标记的连接，透明代理不会把请求重新送入故障代理。macOS 或 Windows 的 TUN 模式不保证这种绕过方式。服务器检查可能启动临时核心进程，但自动更新不会启动用户手动停止的主核心。

升级时，旧的全局“启动时更新”会迁移为每个现有订阅的**服务启动时**模式；旧的定时模式会迁移为**按间隔**，并把小时换算为分钟。迁移不会自动启用故障恢复，需要时请手动选择。

## 自动维护代理组成员

添加代理列表和订阅中的所有服务器，包括不可用的服务器。 更新成员不会测延迟、测速或启动检测核心。

最多同时运行一个检测核心。TCP 延迟决定顺序；URL 和完整的 256 KiB 样本验证至少 100 KiB/s。无合格服务器时阻断组流量。

- 测量所有服务器的 TCP 延迟，按延迟顺序逐个测速，找到首个合格服务器即停止。

- 每个设定的检测周期只检查当前服务器及其速度。URL 失败或速度低于 100 KiB/s 时，按 TCP 延迟和速度选择替代服务器。

- 逐个检查成员，在通过 URL 和速度检测的服务器之间轮流分配新连接。

- 测量延迟后随机排列可达服务器，逐个测速，直到找到合格服务器。

升级时，只有至少一个订阅使用了旧的自动选择，且 `PROXY` 的所有现有成员均来自这些订阅（或该组为空），才会启用自动成员管理。如果存在独立服务器或其他订阅的节点，`PROXY` 会保持手动并保留选择。两种情况下都会移除旧标志；日志会说明如何手动启用**自动添加所有服务器**。迁移只执行一次，不覆盖用户后续的选择。
