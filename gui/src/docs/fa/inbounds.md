# ورودی‌ها و اشتراک‌گذاری

ورودی پورتی است که هسته روی آن اتصال‌های برنامه‌ها یا دستگاه‌های دیگر را می‌پذیرد.

## ورودی‌های داخلی

**تنظیمات → نشانی و پورت‌ها** آن‌ها را تنظیم می‌کند؛ 0 ورودی پروکسی را می‌بندد و برای پورت API باعث انتخاب تصادفی پورت می‌شود.

| ورودی            | پیش‌فرض | مسیریابی                                                                    |
| ---------------- | ------- | --------------------------------------------------------------------------- |
| SOCKS5           | `20170` | همهٔ ترافیک از `proxy`                                                      |
| HTTP             | `20171` | همهٔ ترافیک از `proxy`                                                      |
| SOCKS5 با قوانین | خاموش   | حالت پورت قوانین                                                            |
| HTTP با قوانین   | `20172` | حالت پورت قوانین                                                            |
| VMess با قوانین  | خاموش   | ورودی VMess برای دستگاه‌های دیگر؛ صفحه پیوند اشتراک‌گذاری آن را نشان می‌دهد |
| API              | تصادفی  | API خود هسته که v2rayA برای آمار و متعادل‌سازی بار از آن استفاده می‌کند     |

ورودی‌های پروکسی روی `127.0.0.1` گوش می‌دهند. **اشتراک‌گذاری پورت** (تنظیمات → پروکسی) باعث می‌شود روی همهٔ رابط‌ها گوش دهند تا تلفن‌ها و دستگاه‌های دیگر در شبکهٔ محلی بتوانند از آن‌ها استفاده کنند؛ پورت API روی رابط loopback می‌ماند. در شبکه‌ای که به آن اعتماد ندارید، برای دستگاه‌های دیگر ورودی سفارشی با نام کاربری و گذرواژه اضافه کنید و پورت‌های داخلی SOCKS و HTTP را که گذرواژه نمی‌گیرند ببندید، یا آن‌ها را در دیوار آتش مسدود کنید.

## ورودی‌های سفارشی

**تنظیمات → پورت‌های ورودی سفارشی** ورودی‌های SOCKS یا HTTP را با پورت مستقل، نام کاربری و گذرواژهٔ اختیاری و مسیریابی مستقل اضافه می‌کند: یا یک گروه پروکسی ثابت، یا قوانین RoutingA مخصوص همان ورودی با گروه انتخاب‌شده برای ترافیکی که با هیچ قانونی تطبیق ندارد (`default:` در اینجا نادیده گرفته می‌شود). بنابراین دو ورودی سفارشی می‌توانند ترافیک را به دو گروه متفاوت بفرستند؛ همچنین ورودی‌ای که قوانینش به `network(tcp, udp) -> direct` ختم شود، ترافیک هر برنامه‌ای را که از آن ورودی استفاده کند بدون عبور از پروکسی می‌فرستد.

برچسب، نام ورودی در پیکربندی هسته و در شرط‌های `inboundTag(...)` است.

## Docker و نگاشت پورت

در کانتینری که با `--network=host` راه‌اندازی شده، ورودی‌ها و پروکسی شفاف روی میزبان عمل می‌کنند. در شبکهٔ bridge، پورت 2017 و پورت‌های ورودی مورد استفاده را به پورت‌های میزبان نگاشت کنید و اشتراک‌گذاری پورت را روشن کنید تا روی رابط‌های کانتینر گوش دهند؛ در این حالت پروکسی شفاف فقط کانتینر را می‌بیند. v2rayA نمی‌تواند تشخیص دهد که پورت نگاشت‌شده روی میزبان آزاد است یا نه.
