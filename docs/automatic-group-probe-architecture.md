# Group membership and bounded probing

Membership copies the complete catalog, including unavailable nodes. It performs no network checks and never launches a probe core. Explicit membership refresh uses the saved policy and does not force a selection pass.

All isolated checks share one cancellable process slot. The slot remains held until the child process exits and is reaped. At most one isolated core runs alongside the traffic core, including manual HTTP latency tests and subscription recovery. Candidates are checked sequentially; no group gets its own parallel process pool.

Least latency first performs bounded direct TCP pings (up to eight sockets, with interception bypass), then tests candidates in ascending latency order. UDP-only transports with no TCP listener are checked through their real protocol after TCP-reachable candidates. A full URL check and 256 KiB speed sample must succeed at >=100 KiB/s. The first passing candidate wins; later candidates are not started. Keep current checks its current candidate at the configured interval and retains a reachable node even when its speed is low or unknown. Three consecutive reachability failures, with confirmation checks three seconds apart, trigger the same speed-qualified replacement search. Random shuffles TCP-reachable candidates before sequential speed checks. Round robin checks its members sequentially and uses only passing members. New candidates need a successful speed measurement; if none qualify, the group fails closed without deleting its members.

Subscription fail-safe recovery tests one candidate at a time and stops on the first successful URL check. A speed-test failure alone does not imply every subscription endpoint is unavailable.

The firstavailable strategy is removed from the UI and new API settings. Existing persisted values normalize to leastping; explicit fixed selections remain fixed. Membership and selected-route updates are separate: catalog changes cannot discard unhealthy nodes, and switching the selected route does not rewrite membership.

Connection identity hashes the parsed connection parameters without the display name. Catalog revisions sort these identities, so subscription reordering, renumbering, query ordering and display-name changes do not invalidate selection or restart the core. Real membership or transport/credential changes make Keep current run the least-latency speed-qualified search again. The policy remains Keep current. Every automatic policy remains unchanged when its selected server changes; a manual pin pauses the policy, and clearing the pin resumes it. Legacy persisted fingerprints are migrated before workers start.

Subscription retrieval and group health checks have independent schedules, while their isolated checks still share the single process slot. Database mutations remain serialized. A real subscription change invalidates selection in the same transaction as its catalog and reference updates. This pending state survives multiple updates, including a change back to an older catalog, until a fresh selection commits. Selection results are checked against the current policy and catalog before commit; stale results are discarded. Core updates compare the desired route against the signature of the running template, including after subscription changes.

Group switches preserve unchanged TPROXY/REDIRECT interception and policy routes, including installations with lifecycle hooks. Failed startup and failed rollback retain interception until explicit stop or recovery. Configurations whose interception cannot be preserved reject the switch before stopping the current core (including TUN); they never fall back to an unprotected reload. Rules that intentionally route directly remain direct, and empty proxy groups resolve to blackholes. Existing TCP sessions can still end when a real server change requires a core restart; unchanged subscriptions do not require that restart.

Proxy-tagged UDP DNS uses datagrams through the selected dispatcher. UDP failure or truncation retries TCP through the same outbound, never through an implicit direct connection. Context cancellation closes the dispatcher connection even when its deadline methods are ineffective.

Validation must cover cancellation, concurrent requests sharing the process slot, retained dead members, early stop, low/unknown speed, current-server failover, legacy settings, and one OpenWrt VM with process-count sampling during concurrent operations. The one-process bound reduces peak memory; it does not prove that unrelated core memory growth is resolved.
